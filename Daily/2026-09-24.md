### dailyStats แทน usageEvents รายรอบ

- Collection `dailyStats` เอกสารละวัน (`YYYY-MM-DD`) ฟิลด์ `activeUsersCount`, `totalBookings`, `hours.{0–23}`, `updatedAt`
- เริ่มซัก: `increment(1)` ที่ `totalBookings` และชั่วโมงนั้น — ไม่สร้างเอกสาร `usageEvents` ใหม่ทุกคลิก
- เปิดแอปครั้งแรกของวันต่อเบราว์เซอร์: `increment(1)` ที่ `activeUsersCount` (กันซ้ำด้วย localStorage)
- กราฟ `/admin` อ่าน `dailyStats` แทน query ทั้งเดือนของ `usageEvents` (กราฟเก่าก่อนวันนี้จะว่างจนกว่าจะมีรอบใหม่)
- ต้อง **Publish** `firestore.rules` ที่มี `match /dailyStats/{dateId}` ไม่เช่นนั้นตัวเลขไม่ขึ้น

### ค่าใช้จ่ายโควต้าต่อวัน (หลังลด reads แล้ว)

แผน **Spark (ฟรี)** โดยประมาณ — ดูของจริงใน Firebase Console → Usage:

| โควต้า | เพดาน/วัน (Spark) |
|---|---|
| Reads | 50,000 |
| Writes | 20,000 |
| Deletes | 20,000 |

ฐาน: 53 เครื่อง, cron-job.org ยิง `/api/cron/tick` **ทุกนาที = 1,440 รอบ/วัน**  
Firestore: คิวรีที่คืน 0 เอกสารยังคิดอย่างน้อย **1 read**

#### Reads — ฝั่งเซิร์ฟเวอร์ (cron) คงที่ทุกวัน

| รายการ | สูตร | เงียบ (ไม่มีคนซัก, ไม่มีคนเฝ้า) | ปกติ (สมมติ 5 เครื่องไม่ว่าง + 5 ใบเฝ้า) |
|---|---|---|---|
| `machines` ที่ยังไม่ว่าง | เอกสารที่แมตช์ × 1,440 | ~1,440 (คิวรีว่าง) | ~7,200 |
| `machineWatches` ทั้งชุด | จำนวนใบเฝ้า × 1,440 | ~1,440 (คิวรีว่าง) | ~7,200 |
| `getDoc` เครื่องที่เฝ้าแต่ไม่อยู่ในคิวรี busy | ตามจำนวนใบ | 0 | 0–หลักพัน |
| `pushTokens` ตอนส่งแจ้งเตือน | ต่อ uid ที่ต้องดัน | 0 | สองหลักต่อรอบที่เสร็จ/ใกล้เสร็จ |
| ลบ log เก่า 03:00 น. | สูงสุด 400+400 | ~2 คิวรี | สองหลักถึงหลักร้อย |

**Cron รวมประมาณ 3,000 reads/วัน ถ้าเงียบ** และ **~15,000 reads/วัน** ถ้ามีเครื่องไม่ว่าง/ใบเฝ้าไม่กี่ใบ  
ถ้าเฝ้าเครื่องว่างทิ้งไว้เยอะ ใบ `machineWatches` × 1,440 จะพุ่ง — อย่าให้ค้างเป็นสิบ ๆ ใบทั้งวัน

#### Reads — ฝั่งผู้ใช้ (เปิดเว็บ)

| การกระทำ | Reads ประมาณ |
|---|---|
| เปิดแดชบอร์ด/จอสถานะ «ทุกหอ» | 53 (`machines`) + ประกาศ + ใบเฝ้าของตัวเอง |
| เปิดแดชบอร์ด เลือกหอ 3–4 อย่างเดียว | **5** แทน 53 |
| เปิดหน้าเครื่อง (สแกน QR) | **1** |
| เปิด `/admin` | 53 เครื่อง + กราฟ `dailyStats` วันนี้ 1 ใบ + ทั้งเดือน ~30 ใบ + ล็อกซ่อมทั้งคอลเลกชัน |
| เริ่มซัก / ยกเลิก / เอาผ้า | 1 ต่อธุรกรรม (เอกสารเครื่องนั้น) |
| คนเปิดแอปครั้งแรกของวัน | 1 write ที่ `dailyStats` (ไม่ใช่ read หลัก) |

สมมติ 20 คน/วัน เปิดแดชบอร์ดทุกหอครั้งเดียว ≈ **1,000+ reads**  
จอสถานะเปิดค้างทั้งวัน: จ่าย 53 ตอนต่อ แล้วจ่ายเพิ่มทีละ 1 ทุกครั้งที่เครื่องในชุดนั้นอัปเดต

#### Writes / Deletes

| รายการ | ประมาณ/วัน |
|---|---|
| เริ่มซัก | 1 อัปเดตเครื่อง + 1 `dailyStats.increment` ต่อรอบ |
| คนเปิดแอป (unique ต่อเบราว์เซอร์/วัน) | 1 `dailyStats` |
| ติ๊กเปลี่ยนสถานะ (เสร็จ / ใกล้เสร็จ / ปล่อยผ้าค้าง) | 1–2 ต่อเหตุการณ์ + ล็อก `auto_release` |
| ลบ watch หลังเครื่องว่าง / ลบ log เก่า | deletes นับแยก |

รอบซัก 50 ครั้ง/วัน ≈ **หลักร้อย writes** — ไกลจากเพดาน 20,000
